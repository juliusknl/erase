# Broker scale, without a fake privacy score

`catalog/broker-scale.yml` contains a small, manually researched set of official
database-size claims. It is presentation metadata only: it does not change request
priority, contact verification, sending eligibility, or case outcomes.

The overview highlights requests at these databases. Quick wins, broker details,
and request details show the same evidence. Sources are linked, dated when checked,
and labelled company-reported. The reviewed examples are **not** a comprehensive
list or a ranking of major brokers. Missing evidence means unknown, not small.

Keep the units and qualifications intact. Person records, business contacts,
devices, and customer counts are not interchangeable. Do not add database sizes
together, infer that a broker holds the user's information, or claim a percentage
of exposure removed. A broker's global database size also does not establish the
scope of a regional deletion request or deletion at downstream customers.

Done retains the dashboard's existing meaning: user-completed steps, broker-reported
deletion, and no-match responses. Each highlight shows which evidence underlies
its status and links to the request. A standalone checklist tick without a linked
case does not invent a completed broker request.

To add an entry, verify a primary source and record its domain, name, size, unit,
context, source URL, source limitations, and check date. Restart the local app to
load updated metadata. Claims are dated snapshots, not live counters; recheck them
before advertising current coverage. Apollo's sources currently disagree on the
total, so the entry explicitly attributes the selected article's figure.

Tests cover mixed outcomes, empty accounts, missing metadata, exact domain matching,
source provenance, mobile layouts, and both types of completed checklist icon.
